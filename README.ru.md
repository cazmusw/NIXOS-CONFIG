# Конфигурация NixOS

## Где что менять

```text
flake.nix                 источники nixpkgs и точка входа
flake.lock                закреплённые ревизии источников
hosts/nixos/              настройки этого компьютера: диски, пользователь
modules/system/           загрузка, сеть, локаль, Nix, Docker
modules/hardware/         графика, NVIDIA, ядро, звук, питание
modules/desktop/          Labwc, вход, авторизация, порталы, тема
modules/applications/     установка и настройка приложений
settings/                 списки приложений, XML и INI рабочего стола
versions/                 выбор источников и закрепление версий
  packages.nix            каждый пакет: источник и атрибут
  craft.nix               версии и SHA256 пяти Craft-приложений
  labwc.nix               версия и хеш исходников Labwc
  system.nix              семейство ядра и ветка драйвера NVIDIA
overlays/                 применение выбора пакетов
tests/                   проверки механизма выбора версий
```

`hosts/nixos/hardware-configuration.nix` содержит аппаратную конфигурацию;
при переносе на другой компьютер её нужно заменить результатом
`nixos-generate-config`. `system.stateVersion` сохранён как `26.05`.

## Выбрать stable или unstable для одного приложения

В `versions/packages.nix`:

```nix
firefox = { source = "unstable"; };
```

Остальные записи можно оставить на `stable`. Используются ревизии из
`flake.lock`, поэтому переключение источника само по себе ничего не обновляет.
Выбор применяется к системному пакету и ссылкам `pkgs.firefox` в модулях.
Внутренние зависимости пакета остаются из его исходного набора nixpkgs.

Можно выбрать альтернативный атрибут из того же источника:

```nix
firefox = { source = "stable"; attribute = "firefox-esr"; };
```

## Закрепить отдельное приложение на конкретной версии

У nixpkgs нет универсального `version = "любая версия"`: нужен рецепт сборки
из подходящей ревизии либо отдельный рецепт с исходниками и хешами.

1. Найди коммит nixpkgs, содержащий нужную версию приложения.
2. Добавь в `inputs` файла `flake.nix` независимый источник:

   ```nix
   firefox-pin.url = "github:NixOS/nixpkgs/ПОЛНЫЙ_SHA_КОММИТА";
   ```

3. В `versions/packages.nix` укажи его имя и, если нужно, проверку версии:

   ```nix
   firefox = {
     source = "firefox-pin";
     expectedVersion = "НУЖНАЯ_ВЕРСИЯ";
   };
   ```

4. Выполни `nix flake lock` в корне конфигурации. Эта команда добавит отсутствующий
   источник, сохранив уже закреплённые записи.
5. Проверь сборку командами ниже.

Значения заглавными буквами — шаблоны, замени их реальными значениями.
`expectedVersion` только проверяет версию: при несовпадении вычисление завершается
ошибкой. Для каждого приложения можно завести свой независимый input.
Для сложных пакетов смена ревизии может потребовать совместимого рецепта или модуля.

Если нужна версия, которой нет в nixpkgs, добавляй отдельный рецепт пакета:
одной смены поля `version` недостаточно, особенно для Electron, Rust и Go.

## Labwc и Craft

У Labwc сохранена сборка `0.20.3`. Меняй `version` и `hash` вместе в
`versions/labwc.nix`. Чтобы использовать готовый пакет из `packages.nix`, задай
`version = null`; тогда отдельный хеш не используется.

Для Craft меняй `version` и `sha256` в соответствующей записи `versions/craft.nix`.
URL AppImage строится автоматически. После обновления проверь запуск приложения.

Ядро и NVIDIA настраиваются в `versions/system.nix`. Драйвер выбирается из
пакетов выбранного ядра, чтобы сохранить соответствие модулей.

## VibeShell

Пакет берётся из GitHub через input `vibeshell` с ревизией из `flake.lock`.
Для обновления выполни `nix flake update vibeshell`, проверь сборку и
закоммить обновлённый lock-файл.

После применения конфигурации выйди из Labwc и войди снова. UWSM запустит
пользовательские службы `mosaic-services` и `mosaic-shell` для этой сессии.
Журналы можно посмотреть командой
`journalctl --user -u mosaic-services -u mosaic-shell -b`.

Папки открываются в Mosaic Files. Если в пользовательском
`mimeapps.list` папки были назначены Thunar, служба меняет эту запись
через GIO. В проводнике файлы открываются приложениями для своих MIME-типов.
Пункт «Назначить по умолчанию» в центре приложений меняет обработчик
выбранного типа для текущего пользователя.

## Добавить приложение

Добавь имя атрибута в подходящую группу `settings/package-groups.nix` и запись
источника в `versions/packages.nix`. Специальные настройки приложения размещай
в `modules/applications/` и подключай через его `default.nix`.

## Установка одним скриптом

Из папки этой конфигурации:

```sh
# Сначала только собрать и проверить, без изменения системных файлов.
bash ./install.sh --check

# Установить конфиг в /etc/nixos и сразу применить настройки.
sudo bash ./install.sh
```

Скрипт работает с конфигурацией рядом с собой, независимо от текущей папки.
Сначала он создаёт временный снимок файлов и собирает систему, не обновляя
`flake.lock`. При успешной сборке переносит прежний `/etc/nixos` в отдельную
папку `/etc/nixos.backup.ДАТА.СЛУЧАЙНЫЙ_СУФФИКС`, устанавливает новую копию
и выполняет `nixos-rebuild switch`.

Если сборка не удалась, системные файлы не меняются. Если применение завершилось
ошибкой, прежняя папка конфига восстанавливается; неудачный новый конфиг остаётся
в `/etc/nixos.failed.*/config` для диагностики. Переключение могло успеть изменить
часть служб, поэтому при необходимости отдельно выполни:

```sh
sudo nixos-rebuild switch --rollback
```

Эта команда откатывает системное поколение. После успешной установки исходные
файлы можно вернуть из указанной резервной копии отдельно от отката поколения.
Скрипт не перезагружает компьютер. Он также поддерживает повторный запуск из
самого `/etc/nixos`. Если `/etc/nixos` — символическая ссылка, установка
останавливается до изменения файлов.

Справочник: [параметры nixos-rebuild](https://github.com/NixOS/nixpkgs/blob/master/pkgs/by-name/ni/nixos-rebuild-ng/nixos-rebuild.8.scd).

## Проверка и применение

Выполняй из корня этой папки:

```sh
# Проверка вычисления полной системной derivation, без сборки и переключения.
nix eval --raw .#nixosConfigurations.nixos.config.system.build.toplevel.drvPath

# Проверки выбора источников, закрепления и ошибок версии.
nix eval --impure --json --expr 'import ./tests/versions.nix { flake = builtins.getFlake (toString ./.); }'

# Собрать систему без переключения.
nix build .#nixosConfigurations.nixos.config.system.build.toplevel --no-link

# Применить после успешной сборки, если решишь использовать этот конфиг.
sudo nixos-rebuild switch --flake .#nixos
```

Если добавляешь конфиг в Git, перед проверкой добавь новые файлы в индекс:
flake из Git не видит неотслеживаемые файлы.

Для обновления конкретного канала: `nix flake update nixpkgs` или
`nix flake update nixpkgs-unstable`. Независимые `*-pin` при этом не обновляются.

Справочники: [закрепление inputs](https://nix.dev/manual/nix/2.34/command-ref/new-cli/nix3-flake-lock.html),
[переопределение пакетов](https://nixos.org/manual/nixpkgs/stable/#sec-pkg-overrideAttrs).
